### Traps that cost time (record these)
- V1 tracks are glTF **CUBICSPLINE**: `track.values` is **12 floats per key**
  (in-tangent, value, out-tangent). Reading `values[i*4]` returns tangents —
  unnormalized, often `[0,0,0,0]` — which mimics a file full of corrupt keys.
  Real value is `values[i*12+4]` and has magnitude 1.0000. Never hand-read
  `values`; sample through `AnimationMixer`.
- **429 shared typed-array buffers** across V1 tracks (even across clips).
  In-place `values` mutation corrupts neighbours, which then look corrupt.
  Deep-copy (`track.clone()`) before any repair.
- `AnimationClip.clone()` needs `track.clone()`, not a fresh `KeyframeTrack` —
  the plain class drops the quaternion slerp interpolant and reports ~10,000 deg/s.
- `accents` is NOT gateable (V1 takeoff 2 vs V2 93 for the same clip). Removed
  from `GATE`, kept in the report.
- `bankLeft`/`bankRight` near-identical maxima are **mirror invariance**, not a
  duplicated clip (different peak joints, different hashes). Verified.
- toybox `grep -c` undercounted gate failures 27 -> 18. Count in node.

## Stage 3 diagnosis + first fix — landed

- `tools/diagnose-clip-dynamics.mjs`: adds **travel** (cumulative |dq|, unbounded)
  next to the gate's rate. `range` is reported but saturates at 180 deg and is
  not to be trusted — my first version used it and every clip read exactly 180.0.
- `tools/amplify-clip.mjs`: exaggerates a clip by scaling each bone's rotation
  about the clip's **first key**, axis preserved. Patches float32 values in place:
  measured, animation accessors are buffer 0, uncompressed, one per bufferView, and
  the compressed mesh region ends at byte 695,961 while animation starts at 695,964
  — **0 overlaps**, so geometry is untouched by construction.
- `tools/build-dynamics-candidate.mjs`: solves each gain (walks down from the
  travel-gap gain until capped keys <= 2%) instead of hardcoding. Refuses plateaus:
  a capped key is a pose frozen at 160 deg, which raises mean/p95 while looking
  like a hitch — doc 36's lesson applied to the fix tool itself.
- `test/wyvern-clip-dynamics-tools.test.js` (12). Suite 161 pass, tsc clean.
- Gate: **27 failing checks -> 20**. cruise all four channels green; both banks
  peak+p95 green, mean short (0.586 vs 0.7 floor). Shipped rig NOT changed —
  candidate lives at `assets/rig-audits/2026-10-21-dynamics/candidates/`.
- Docs: `docs/flight-lab/37-stage3-clip-defect-taxonomy.md`.

### The taxonomy (the actual finding)
One axis, `sustainRatio = p95R/travelR`:
- **UNIFORM** (0.6–1.4): cruise, bankLeft, bankRight, attack -> gain applies.
- **CONCENTRATED** (<0.6): idle, walk, attack2 -> travels but does not sustain.
- **BUZZ** (>1.4): takeoff, death -> fast through a small range.
`peak` is NOT the discriminator (idle peakR 0.423 looks half-alive; p95R 0.077).

### Structural facts worth not re-deriving
- V2 has **zero CUBICSPLINE**; all LINEAR or STEP. STEP only on <=2-key channels
  (verified: 0 STEP samplers have >2 keys) -> harmless, encodes static poses.
  LINEAR cannot overshoot, which caps peak independently of amplitude.
- V2 `attack` animates 43 of 92 rotation channels; V1's AttackBite animates 144 of
  218. 49 channels are constant poses. **No gain animates an unkeyed bone.**
- `attack` needs 12.3x but caps at 3.5x. That ceiling is a coverage artefact.

### Traps I fell into this session (record)
- **Circular check**: I "confirmed" travelRatio/durationRatio == rateRatio with
  zero residual — but `travelRate = travel/duration` **by definition**, so that
  ratio is a tautology. The real residuals were 10–54%. Compare peak/mean ratios,
  never a derived ratio against its own inputs.
- **`num()` fed header labels** — twice, in two different tools (`TypeError:
  v.toFixed is not a function`). Keep `label()` separate from `num()`.
- `norm()` in amplify-clip is a **quaternion** normaliser; passing a 3-vector
  yields NaN (hypot with undefined). Normalise 3-vectors inline.
- Mesh bufferViews in the V2 GLB have `"buffer": 1` (meshopt decompressed target)
  with the compressed blob in buffer 0. Reading `binStart + byteOffset` for a
  buffer-1 view reads animation data — that is what made my geometry test fail.
- `fromAxisAngle` must normalise its axis; an unnormalised axis gives a non-unit
  quaternion and `angleOf`'s acos/hypot then disagree silently.
- Dead code with a comment claiming it matters: the `d = norm(...)` in `amplify`
  is a no-op because both operands are normalised first. Mutation testing showed
  it survived, so I moved the normalisation to the inputs where it is load-bearing
  (mutating `unitQ = norm(q)` -> `q` gives a 0.87 deg error and 2 red tests).
