## The bug found on the way (affects the existing `Scan`)

**Writing a bone rotation and then calling `mixer.update(0)` on a paused action leaves that action
unable to write the pose again.** Reproduced minimally: reset `bone.quaternion`, `mixer.update(0)`,
then seek again → the bone reads untouched, forever. `scanSeam` borrows the playback mixer, so a
**second `Scan` press in one session measures a stale pose and reports the clip clean**. Measured:
first `sampleClipPoses` −21.1°, every later call identity.

Fix used here: `sampleClipPoses` runs a **private `AnimationMixer`**, and reports bind values for
bones the clip does not animate (rather than resetting the scene, which is what poisons the mixer).
Regression test asserts a repeated scan reproduces the first result. **`scanSeam` still has the
defect** — left alone as out of scope.

## D4 flight group closed — cruise, bankLeft, bankRight (asset `b5f1c1ef…`)

**What was believed:** cruise needed 1.68× and the membrane span test blocked it; the banks needed
6.7× which broke the 8% cadence lock. Both measurements were right; both diagnoses were of the wrong
variable.

**What is true:** the flight group beat at **0.500 Hz** against V1's **1.000 Hz**. Velocity is
amplitude × frequency, so half the cadence is half the dynamics — cruise's `0.480×` peak and
`0.518×` mean are almost exactly 2× short for that reason alone.

- `cruise`: retime every channel's key times by `0.5` (6.000 s → 3.000 s), poses untouched →
  `peak 734.6 / p95 663.8 / mean 395.1`, gate clear. `maxMembraneX` at `t = 1.0 s` **rises** to
  `2952.7` (was 2780.9) because the sampled frame lands on the extension, so
  `test/wyvern-v2-kinetics.test.js` passes **unmodified** — no span-test rewrite was needed, and the
  cycle-peak rewrite proposed in doc 41 would not have worked either (a 1.8× gain puts the *cycle
  peak* at 2211.7, below 2500; the fold is real everywhere).
- `bankLeft`/`bankRight`: retime `0.5` **plus** a `1.95×` gain → `2547 / 1794 / 700`. At 0.5 Hz the
  same gain drove the wingtip to `x = -1007.7` (through the midline); at 1.0 Hz the cycle minimum is
  `+117`. Same parameters both sides, so the mirror pair holds.
- Validator: `1.000 / 1.000 / 1.000 Hz`, spread `0.0%`, clean. Gate: `PASS` on all nine.
