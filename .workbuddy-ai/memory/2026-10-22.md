## The bug found on the way (affects the existing `Scan`)

**Writing a bone rotation and then calling `mixer.update(0)` on a paused action leaves that action
unable to write the pose again.** Reproduced minimally: reset `bone.quaternion`, `mixer.update(0)`,
then seek again → the bone reads untouched, forever. `scanSeam` borrows the playback mixer, so a
**second `Scan` press in one session measures a stale pose and reports the clip clean**. Measured:
first `sampleClipPoses` −21.1°, every later call identity.

Fix used here: `sampleClipPoses` runs a **private `AnimationMixer`**, and reports bind values for
bones the clip does not animate (rather than resetting the scene, which is what poisons the mixer).
Regression test asserts a repeated scan reproduces the first result. **`scanSeam` still has the
defect** — left alone as out of scope.
